\# 🚀 Day 3 总结：从“写脚本”到“做工程”的跨越（P1 阶段：Python 工程化）


\## 🎯 一、今日战果（产出清单）

严格执行“每天目标”SOP，完成了从流水账脚本到标准工程结构的重构：

1\. \*\*搭建虚拟环境\*\*：成功使用 `python -m venv venv` 创建无菌室，并通过 `pip freeze > requirements.txt` 导出了项目依赖配方。

2\. \*\*工程化重构\*\*：将昨天几十行的 `auth\_parser.py` 拆解成了大厂标准的模块化结构：

&#x20;  - `config.json`：存放文件路径和关键字配置。

&#x20;  - `logger.py`：封装了带时间戳和级别（INFO/WARNING/ERROR）的日志记录器，彻底告别 `print`。

&#x20;  - `parser.py`：只负责核心的日志解析和 IP 统计逻辑。

&#x20;  - `main.py`：作为总控室，读取配置、调用逻辑、输出日志，外加 `if \_\_name\_\_ == '\_\_main\_\_':` 护城河。

3\. \*\*Git 仓库规范化\*\*：新建了 `.gitignore` 文件，成功将笨重的 `venv` 文件夹和 `\_\_pycache\_\_` 缓存屏蔽，保持仓库整洁。

\## 🧠 二、知识图谱（学到了什么）

\* \*\*模块与包\*\*：明白了任何 `.py` 文件都是一个模块。掌握了 `import xxx`（拿整个工具箱）和 `from xxx import yyy`（精准拿工具）的区别。

\* \*\*神奇的 `\_\_name\_\_` 变量\*\*：理解了当文件被直接运行时，`\_\_name\_\_` 等于 `'\_\_main\_\_'`；当被当做模块导入时，`\_\_name\_\_` 等于文件本身的名字。这就是“护城河”防误触的底层原理。

\* \*\*虚拟环境与依赖\*\*：明白了环境隔离的重要性。知道了 `pip install -r requirements.txt` 是一键复现别人环境的终极魔法。

\* \*\*日志系统（logging）\*\*：掌握了日志的五种级别（DEBUG/INFO/WARNING/ERROR/CRITICAL），以及如何通过 `Formatter` 格式化输出，这对于以后排查大模型线上问题至关重要。

\* \*\*PEP8 规范\*\*：掌握了变量全小写+下划线、缩进必须是 4 个空格、以及 import 语句的推荐排列顺序（标准库 -> 第三方 -> 自定义）。

\## 💣 三、踩坑与排雷（程序员的日常）

1\. \*\*Windows 的“刁难”\*\*：在 CMD 输入 `python` 却弹出微软商店，学会了去系统设置里关闭“应用执行别名”，重新找回真正的 Python 路径。

2\. \*\*`.gitignore` 的创建\*\*：在 Windows 系统里直接右键新建不叫这个名字，学会了使用记事本“另存为”，并用英文双引号包裹文件名。

3\. \*\*报错家族大乱斗\*\*：在测验中，把模块找不到的 `ModuleNotFoundError` 记混成了文件找不到的 `FileNotFoundError`；另外还手误把 `freeze` 拼成了 `frezee`。

4\. \*\*导入逻辑的模糊\*\*：把 `from logger import get\_logger` 与 `import logger` 的调用方式搞混，错以为要用 `logger.get\_logger()`，现在彻底理清了“掏出来直接用”和“带着工具箱用”的区别。
